# ARC-Apache Master Spec v4

## Mission

ARC-Apache is the binary memory substrate for ARC. Its job is to store every durable fact, runtime action, payload, frame, language artifact, model artifact, repository state, and seeded-generation reference as deterministic binary first, then bind that binary to cryptographic receipts.

The rule is absolute:

```text
No durable ARC truth exists until it has a binary object identity and receipt lineage.
```

## System shape

```text
operator / model / sensor / file / repo / stream / simulator
        ↓
canonical object adapter
        ↓
ARC binary envelope
        ↓
chunk store + payload hash + Merkle root
        ↓
manifest hash
        ↓
ARC receipt
        ↓
ARC-Core registration
        ↓
views: text, JSON, embeddings, search, UI, model training rows
```

## Canonical binary object

An ARC binary object is not merely a file. It is a deterministic envelope:

```text
magic bytes
version
content class
codec
payload length
payload bytes
payload sha256 footer
```

The minimal v4 header is intentionally simple so the proof path works everywhere. Future versions may add CBOR/MessagePack/protobuf, compression, encryption, and signatures, but the current reference path avoids pretending those features exist before they are validated.

## Object classes

| Class | Meaning |
|---|---|
| `runtime_event` | commands, actions, outputs, branches, errors, policies |
| `language_graph` | language DB mirrors, seeds, corpus manifests, concept graphs |
| `stream_frame` | screenshot, camera frame, audio/video segment, UI state |
| `stream_sequence` | ordered frame/session manifest |
| `model_artifact` | GGUF, tokenizer, checkpoint, benchmark artifact |
| `dataset_capsule` | training/eval rows with source payload lineage |
| `repo_state` | tar/git bundle/snapshot/release proof |
| `seed_recipe` | SURE generator+seed+parameter+environment capsule |
| `generic_blob` | any other payload, still binary-proofed |
| `arc_rar_bundle` | portable archive/rollback package |

## ARC-Core boundary

ARC-Core should register:

- object hash;
- manifest hash;
- Merkle root;
- receipt hash;
- source system;
- object class;
- parent receipts;
- policy status;
- timestamp;
- optional actor/key identity.

ARC-Core should **not** store giant blobs. ARC-Core is the authority spine, not the object warehouse.

## ARC Language Module boundary

The language module is directly part of the binary memory spine. It is not a side dataset.

Language artifacts must be mirrored as binary objects:

- language SQLite database;
- seed JSON files;
- concept graphs;
- transliteration and variant maps;
- pronunciation/phonology data;
- source/corpus/provider manifests;
- tokenizer-related language artifacts.

Runtime events that contain text should link to the relevant language snapshot receipt when possible. This allows ARC to know which lexical truth state existed when the event was created.

## SURE boundary

SURE adds seeded reconstruction. A generated object can be stored as either:

1. exact generated bytes + proof; or
2. seed recipe + generator identity + parameter set + environment fingerprint + output hash; or
3. both.

This is how ARC can approach universal-scale storage: store exact bytes when required, store reproducible recipes when generation is deterministic and verifiable, and always record the proof chain.

## No silent overwrite

Updates create new objects. A changed file, changed language graph, changed model artifact, changed frame, or changed seed recipe gets a new object identity. Old identities remain valid unless chunk-retention policy prunes cold bytes while preserving receipts.

## Professional claim boundary

ARC-Apache is a storage/proof plane. It does not by itself make an AI intelligent. It makes AI memory, training data, visual captures, runtime decisions, and generated worlds traceable, restorable, and falsifiable.
