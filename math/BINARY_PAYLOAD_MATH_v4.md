# Binary Payload Mathematics v4

## Payload identity

For canonical bytes `B`:

```text
payload_hash = SHA256(B)
```

This proves exact byte identity.

## Chunking

For payload length `N` and chunk size `C`:

```text
k = ceil(N / C)
chunk_i = B[i*C : min((i+1)*C, N)]
chunk_hash_i = SHA256(chunk_i)
```

## Merkle tree

```text
level_0 = [chunk_hash_0, chunk_hash_1, ...]
level_{n+1}[j] = SHA256(level_n[2j] || level_n[2j+1])
```

If a level has an odd number of nodes, duplicate the final node. This makes the tree deterministic.

```text
merkle_root = only hash remaining at final level
```

## Manifest identity

The manifest is canonical JSON in v4:

```text
manifest_hash = SHA256(canonical_json(manifest_without_manifest_hash))
```

Then the stored manifest includes the final `manifest_sha256` field.

## Receipt identity

The receipt binds object identity, source, parent receipts, and policy status:

```text
receipt_hash = SHA256(canonical_json(receipt_without_receipt_hash))
```

## Seeded reconstruction

A SURE object stores:

```text
generator_id
generator_version
seed
parameters_hash
environment_fingerprint
expected_output_hash optional
```

A deterministic generator can recreate the object. If exact byte preservation matters, store generated bytes too.

## Deduplication

A content-addressed chunk store deduplicates automatically:

```text
stored_chunks = unique(chunk_hash_i)
```

If two payloads share chunks, the chunks are stored once and referenced by multiple manifests.

## Retention tiers

| Tier | Keep |
|---|---|
| hot | chunks + manifests + receipts + views |
| warm | chunks + manifests + receipts |
| cold | receipts + manifests + selected chunks |
| archive | Arc-RAR bundle or external backup |
| recipe-only | SURE recipe + expected hash, no generated bytes |
